A · Das Paket ein ZIP, höchstens 2,5 GB, Name und Kurs im Dateinamen

Nachname_Vorname_GEC1.zip
├─ Nachname_Vorname_GEC1_Projekt.zip
├─ Nachname_Vorname_GEC1_Build.zip
└─ Nachname_Vorname_GEC1_Dokumentation.pdf
  • Alle drei Teile liegen in einem ZIP. Nur ZIP: kein .rar, kein .7z, kein .tar.
  • Dateinamen mit eigenem Namen und Kurs, wie oben.
  • Gesamtgröße höchstens 2,5 GB. Windows: Rechtsklick › Eigenschaften. macOS: Rechtsklick › Informationen.
  • Hochgeladen in den Prüfungsraum auf Blackboard, nicht erst in der letzten Stunde.

B · Git in dieser Reihenfolge

  • Szenen in Unity gespeichert, committet, gepusht. GitHub Desktop zeigt No local changes, kein Push origin offen. KI-VERZEICHNIS.md ist aktuell.
  • Aus genau diesem Stand gebaut (D) und auf einem fremden Rechner getestet (E).
  • Dann diesen Commit taggen: GitHub Desktop › History › Rechtsklick auf den Commit › Create Tag › abgabe › Push origin. Terminal: git tag abgabe <Kennung>, git push origin abgabe

C · Projekt-ZIP der Stand, den jemand anderes öffnen kann

  • Am einfachsten: auf GitHub Code › Tags › abgabe › Source code (zip) herunterladen und umbenennen. Enthält genau den Stand des Tags.
  • Im ZIP ein Projektordner mit Assets/, Packages/, ProjectSettings/.
  • Dabei liegen DOKUMENTATION.md, KI-VERZEICHNIS.md, AGENTS.md.
  • Nicht im ZIP: Library/, Temp/, Logs/, UserSettings/, obj/, der Build-Ordner.
  • Probe: Das ZIP in einen neuen, leeren Ordner entpacken. Unity Hub › Add › Add project from disk. Öffnen (dauert beim ersten Mal), Startszene öffnen, Play. Die Console zeigt keine roten Fehler.
  • Eigene Dateien liegen in benannten Ordnern (Scripts, Scenes, …). Keine Reste wie New Material (3) oder leere Testszenen.
  • Jedes Skript im Projekt hat oben den Kopfkommentar aus Tag 3: was es tut. Bei Skripten vom Agenten ist er geprüft und verstanden.
  • Keine kostenpflichtigen Assets. Fremde Assets stehen mit Quelle und Lizenz in der PDF.

D · Build-ZIP das Spiel ohne Unity

  • Ein Windows-Build aus File › Build Profiles › Windows, gebaut aus dem committeten und gepushten Stand (B).
  • Der ganze Ordner ist im ZIP: die .exe, der Ordner, der auf _Data endet, UnityPlayer.dll und alles daneben.
  • Ordner, deren Name auf DoNotShip oder ButDontShipItWithYourGame endet, sind nicht im ZIP.
  • Alle Szenen stehen angehakt in der Scene List, die Startszene oben. Development Build ist aus.

E · Build-Test auf einem fremden Windows-Rechner nicht auf dem eigenen

  • Das Build-ZIP per USB-Stick oder Cloud-Link auf den fremden Rechner bringen und in einen Ordner entpacken. Nicht aus der ZIP-Vorschau heraus starten.
  • Die .exe startet. Meldet Windows „Der Computer wurde durch Windows geschützt“: Weitere Informationen › Trotzdem ausführen.
  • Bild, Ton und Steuerung funktionieren. Der Mauszeiger ist da, wo er gebraucht wird.
  • Das Spiel lässt sich von Anfang bis Ende spielen, beide Interaktionen eingeschlossen.
  • Neustart möglich, und das Spiel lässt sich beenden (Menü oder Taste, nicht nur Alt+F4).
