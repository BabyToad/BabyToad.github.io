Was ihr am Ende abgebt

Eine interaktive Spielwelt in Unity. Klein ist erlaubt: Ein einziger Raum reicht.

Wofür es Punkte gibt

  • Idee und Konzept: 30
  • Audio-visuell: 20 · Funktionalität: 20
  • Struktur und Build: 10 · Implementierung: 10 · Dokumentation: 10

Drei Wege zum Spiel

  1. Von Hand im Editor: Objekte, Komponenten, später Knoten im Graphen
  2. Code lesen: verstehen, was ein Skript in jedem Frame tut
  3. Mit einem Agenten: beschreiben, prüfen, übernehmen oder verwerfen

Ein Spiel ist eine Schleife

Jeder Durchlauf ist ein Frame, viele davon pro Sekunde.

Was in einem Frame passiert

  1. Eingabe lesen
  2. Zustand ändern
  3. Bild zeichnen

Eure Skripte laufen im zweiten Schritt. Unity ruft dafür in jedem Frame Update auf: bei jedem eingeschalteten Skript auf einem aktiven GameObject, das diese Methode hat.

Was die Engine euch abnimmt

  • Bilder zeichnen
  • Physik und Kollisionen
  • Eingabe, Ton, Animation
  • Den Build für Windows

Alles ist ein GameObject

Ein GameObject ist zunächst leer. Was es kann, bestimmen seine Komponenten.

Komponenten bestimmen das Verhalten

  • Transform: wo es ist
  • Mesh Renderer: wie es aussieht
  • Collider: womit es zusammenstößt
  • Euer Skript: was es tut

Jede Component ist ein Baustein mit eigenen Einstellungen im Inspector. Auch ein Skript ist eine Komponente.

So arbeiten wir

  1. Beschreiben, was passieren soll
  2. Bauen
  3. Spielen
  4. Prüfen, was sich geändert hat
  5. Committen

Git ist euer Rückgängig-Knopf

Ein Commit ist ein Speicherpunkt. Geht etwas kaputt, springt ihr dorthin zurück.

Was eine KI im Projekt verändert, kommt ins KI-Verzeichnis

Werkzeug, Modell, Zweck, Dateien. Das Verzeichnis ist Pflicht, auch ohne KI-Nutzung.

Zu Hause: Das erste Objekt bewegt sich

Ein Würfel, ein Skript, eine Zeile in Update.

Pro Frame

void Update()
{
    transform.Translate(0, 0.05f, 0);
}

Seht selbst

tempo = 3;

// in Update()
y += tempo
  * Time
  .deltaTime;

Pro Sekunde

void Update()
{
    transform.Translate(0, 3f * Time.deltaTime, 0);
}

Ohne deltaTime gilt Bewegung pro Frame, mit deltaTime pro Sekunde.

deltaTime ist die Zeit seit dem letzten Frame. Wer damit multipliziert, bewegt Objekte pro Sekunde statt pro Frame.

Lasst euch die Zeilen erklären

„Erkläre Zeile für Zeile, was dieses Skript in jedem Frame tut. Ändere nichts.“
